# 1.0.5 Fomo 请求、缓存与频繁切币验证

日期：2026-09-28。

## 发布基线

本版本基于本仓库 1.0.4（`5996ecb`），保留 Arc、HyperEVM、Pump 支付金额补全、EVM 个人动态补漏以及公开版诊断关闭配置。1.0.4 的 370 项基线测试通过，新增请求与资源回归后共 406 项测试通过。

## 修复

- 保留持仓/行情每 5 秒刷新；Feed 仅在使用时读取，切换标签补查。Feed/About 不查询隐藏的 Pump 持仓和关注按钮状态。
- 同会话只读请求合并在途调用、成功结果复用 1 秒；当前用户资料缓存 5 分钟，关注列表仍为 10 秒。手动刷新同时绕过关注状态的快照、底层短缓存与临时失败缓存；服务端冷却仍生效。关注/取消关注写操作不缓存。
- 侧边栏切币等待路由稳定 300ms，连续略过的币不逐个请求；自动切币不强刷账号关注列表。离开、隐藏和旧响应乱序有对应保护；已发出的旧 HTTP 不宣称取消。
- Fomo 资料查询按币去重、25ms 合批、每批最多 50 个币、最多两批并发，等待队列最多 512 个币。交易先投递，资料随后补全；容量满时只跳过可选资料补全。
- 401 续期与并发读取合并，失败后停止反复打开登录页。403/430 默认冷却 5 分钟；429 遵守完整 Retry-After，没有该响应头时指数退避；冷却状态保存于浏览器会话，已有可用实时连接继续接收。
- HTTP 短缓存同时限制 128 条、估算总权重 2 MiB、单条 256 KiB。过大响应仍完整交给页面，只不放入短缓存。权重不等于整个扩展的实际内存。
- Token 备用缓存的待写数据按币合并为最新一份，最多 50 个等待币加一个正在写入项；交易历史只保留正在写入和最新待写的完整快照。实时事件不合并丢弃。
- Holders 不创建 Feed 宽限计时器，Feed 提前返回则清除；资料队列只保留请求需要的币地址和链。

## 保留 1.0.4 的业务能力

- 保留 Arc 持仓与交易支持、HyperEVM、Pump 支付金额补全、EVM 钱包映射与个人动态补漏。
- `core.js`、`fomo-api.js`、`pump-api.js`、`gmgn-follow-bridge.js`、`trade-delivery.js`、`runtime-config.js` 与实际 1.0.4 字节一致。MAIN 桥和 Relay 仅更新版本标识。
- Manifest 权限、域名和加载配置未变；只更新版本号。
- 公开版诊断保持关闭，没有增加诊断页面或打开诊断接口。可选诊断分支的等待日志限制为 300 条，仅隔离测试会启用该分支。
- 持仓/PnL 算法、卡片合并规则、逐笔投递及声音逻辑由原有回归继续验证。

## 验证结果

- 原项目 `npm test`：370/370。
- 1.0.5 发布代码 `npm test`：406/406（包含原有功能及新增回归）。
- 所有 `src/*.js` 语法检查通过，补丁检查通过。
- 内置 Chromium 合成页面回归：侧边栏 5 张、浮窗 6 张初始 Holder 卡片各执行 20 轮更新，卡片移出次数均为 0；汇总、金额、展开评论、排序、头像更新和用户移除通过。没有连接真实交易页面。
- 手动刷新关注状态的新回归在修复前复现了底层短缓存返回旧数据，修复后能立即看到变更，并可绕过临时失败缓存；公开版诊断保持关闭。
- 新增边界测试：大响应缓存权重、1,000 次同币/异币慢写、1,000 次历史快照合并、写入失败恢复、10,000 个资料申请再追加 1,000 个、10,000 次连续路由变化、超时后的在途记录释放、Feed 计时器清理。
- 请求预算测试只针对定义的合成场景：同币 12 轮持仓刷新及关注查询共 31 次 Fomo HTTP；30 个不同币、每 2 秒切换的操作及关注查询共 67 次。不含独立实时资料补全、周期任务或 Pump 请求，不是总流量上限或平台风控阈值。

## 边界与启用

本次使用本地模拟，没有真实 Fomo 请求、测试交易、Chrome 长期堆快照或真实账户 A/B，无法据此确认封控原因或保证不会再次限流。

异常大响应会跳过短缓存；写入严重积压时最旧的可选 Token 缓存写入会被放弃，可能减少旧币失败时的备用数据，当前返回的数据仍完整显示。旧持久缓存兼容保留；条数限制不代表整个磁盘缓存的字节配额。

需在 Chrome 扩展管理页重载实际目录对应的扩展，再完整刷新 GMGN 并重新打开侧边栏。仅保存文件不会证明正在运行的后台和页面已经更新。升级包不会自动重载正在使用的浏览器页面。

# 1.0.6 请求削减验证

移除浮层和侧边栏的 About。币资料、Fomo/Pump 持仓和卡片关注状态不再定时刷新；首次进入详情加载，显式刷新/重试仍可查询。Feed 首次打开单独加载。两种面板共享同一详情访问的后台结果，窗口焦点和收起展开不刷新详情。

## 保留的业务路径

- 切换到新币仍加载该币；快速切换沿用原来的 300ms/首屏等待，旧响应不能覆盖新币。
- Fomo 持仓汇总、用户身份、PnL、复制钱包和关注/取消关注的来源及计算不变。Pump 卡片不计入 Fomo 汇总。
- WebSocket、新交易投递、GMGN 原生列表/声音和 REST 补漏校准保留。持仓展示是进入时快照，显式刷新或重新进入详情更新。
- 币资料补查复用 GMGN 已有 `token_info_brief` 封装，按链合并，每批最多 50 个币、单并发、启动间隔至少 5 秒。只补名称、符号、图片和供应量，不使用 GMGN 当前价格覆盖成交价格/成交市值。
- WebSocket 和 REST 补漏先交付交易，异步补资料；资料补全不产生第二次交易通知或声音。GMGN 不可用时不回退到 Fomo 资料普查，也不更改 Fomo 会话。
- 进入详情仍保留一次 Fomo 币资料请求，以维持现有页头字段和持仓比例计算；About 的移除不等于全部 Fomo HTTP 消失。

## 资源与恢复边界

- 后台详情快照最多 8 个标签页，估算缓存体积最多 2MiB，单部分 256KiB；超大结果正常返回但不缓存。
- 资料缓存最多 512 个币，成功结果复用 10 分钟；真实空结果复用 5 分钟；接口未就绪或失败仅退避 15 秒。
- 资料补查队列最多 512 个等待币，加一个至多 50 个币的活跃批次；拥塞只跳过可选资料补全，不丢弃交易。MAIN 查询 6 秒内释放订阅和计时器。
- 导航更换访问标记，重新加载网页创建新标记。账号变化、关注操作和显式刷新使相关结果失效。Fomo 401 续期共享一个恢复过程；403/429 原有退避保留。

## 验证

2026-10-01 本地 `npm test`：419 项通过。全部使用模拟网络/时钟，无真实 Fomo 请求或交易。

| 场景 | 验证结果 |
| --- | --- |
| 同一详情停留 60 秒，反复触发焦点/面板加载 | Fomo 详情相关 HTTP 31 次降至首次的 4 次：资料、持仓、关注列表和当前用户各一次；独立的交易补漏不计入此数 |
| 首次打开 Feed，反复切换 Holders/Feed | 仅新增一次 Feed HTTP，不重查资料和持仓；显式刷新可更新 |
| 新币/重新进入/网页刷新 | 正常重新查询；同一详情中浮层和侧边栏复用结果 |
| GMGN 补查挂起，WebSocket 或 REST 出现新交易 | 首次交易先交付；补全沿用原交易，不重复通知 |
| 10000 次快速切币 | 单个待执行详情定时器，只加载最终稳定币 |
| 10000 个缺资料币突发 | 等待队列、批次并发、缓存、订阅及定时器均受限 |
| 同地址跨链、供应量/图片补全 | 按链隔离，保留原成交金额、成交价和已有成交市值 |

## Pump 真实账号验证（2026-10-01）

- 持仓接口 HTTP 200，返回 50 条记录。真实 GMGN 内容脚本三次查询同一详情均成功复用；137 秒后再查仍成功，持仓 HTTP 计数保持 1 次。
- 关注列表 HTTP 200，当前 7 个关注账号；用户资料和账号动态接口的已完成请求均成功。

- 保留的账号动态补漏每轮检查 7 个当前关注账号。这仍是 Pump 持续 HTTP 请求的主要来源；两份关注列表缓存的启动冗余也尚未修改。
